\section{Introduction}
\label{sec:intro}

For a machine learning system deployed in dynamic environment,
continuous monitoring and adaptation is a necessity to mitigate
performance degradation.

As expected, this is a well-studied problem

fine-tuning is a necessity as the data drifts away from the
distribution that generated the original training data. Adjusting to
data drift is well-studied task, with a rich literature on both how to
detect the drift and on how to minimize the amount of labelling
necessary in order to re-train or fine-tune the system.

In order maximally economize on labelling effort, it makes sense to be
able to extract as much information as possible from the
\emph{unlabelled} deployment data, and use this information to
pin-point the instances that would have the impact on model accuracy.


Tran et al. \cite{tran-etal:2026}: concept drift either synthetically
simulated or simulated by assuming a more fine-grained labelling (such
as CIFAR-100 or ImageNet) as deployment data after training on CIFAR-10.
The latter simulates novel classes, but not drift in the class boundaries.
Synthetic drift sounds a not-very-good idea, will elabortate.

Noting how CIFAR and ImageNet label refer to individual physical
objects, it is unlikely that a noticeable drift can occur.


\paragraph{Contributions}

We present a methodology for characterizing unlabelled instances as
exhibiting data drift or concept drift (or both) and, in the case of
concept drift, for identifying both the direction and the severity of
the drift. Based on this information, we also present a methodology
for selecting a small subset of the unlabelled new instances for
manual annotation, such that fine-tuning on these sub-set only
achieves accuracy on a par with labelling all new instances and
fine-tuning on the complete new dataset. We envisage that this
methodology will become an important part of systems for monitroing ML
systems post-deployment.
